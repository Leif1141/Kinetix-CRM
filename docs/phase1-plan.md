# KinetixCRM phase 1 plan (branch phase1-shell)

Starting point: one index.html of 3,075 lines (594 KB), one Firebase node `crm` rewritten as a 3.2 MB blob on every save, 65 functions wired through inline onclick handlers, a modal editor with about 50 inputs, UI text mixed German and English.

## 1. Code split (no behaviour change)

Native ES modules, no build step, deploy stays a GitHub Pages push.

| File | Holds |
|---|---|
| index.html | Shell markup only, loads styles.css and src/main.js |
| styles.css | All CSS, plus the phone rules from step 6 |
| src/config.js | Firebase config, OAuth client ids, allow-list |
| src/constants.js | STAGES, ACTIVE_STAGES, ADV_STATUS, ADV_CATS, PTYPES, CHANNELS, cadence steps, stale thresholds |
| src/state.js | The in-memory state S, record helpers (findRec, allRecs, touchList, lastTouch, cadenceOf, matchRecords), undo |
| src/util.js | today, addDays, esc, formatters |
| src/store/*.js | Firebase init and auth, per-record store (step 2), legacy blob codec, export and import |
| src/sync/*.js | Outlook, Granola, Drive proxy (patches, backup), patch ops (applyPatchOps unchanged) |
| src/views/*.js | home, orgs, people, pipeline, threads, inbox, reports, map, dash, data, record page, palette |
| src/main.js | Boot, tab routing, renderAll, and the one place that exposes handler functions on window for the existing inline onclick markup |

Handler exposure is a listed compatibility layer; views that are rebuilt in this phase (home, record page, palette) use addEventListener and data attributes instead.

## 2. Per-record Firebase store

Proposed layout (replaces the `crm` blob in place; the blob is copied to `crm_legacy` first and kept until Leif deletes it):

| Path | Content | Written as |
|---|---|---|
| crm/companies/{id} | Company record without touches | ref.update per changed field |
| crm/advisors/{id} | Advisor record without touches | same |
| crm/people/{id} | Person record without touches | same |
| crm/touches/{recId}/{touchKey} | One touch (email, call, Granola note, letter) | one write per new or edited touch |
| crm/threads/{threadId} | Open-items thread (198 today, ids are record ids) | per thread |
| crm/dash/todos/{id}, crm/dash/progress/{id}, crm/dash/decisions/{id}, crm/dash/meta | Dashboard items individually, funnel and counters in meta | per item |
| crm/meta/{name} | senderMap, geoCache, dismissed, dismissedUnmatched, ignoredSenders, ignoredDomains, appliedPatchTitles, appliedPatches, customLists, threadsDone, threadsState, emailMap, snoozeUntil, flags (lastSync, lastBackup, lastDriveBackup, snapshot week, seed version) | per key inside each map |
| crm/inbox/{key} | Unmatched sender items awaiting assignment | per item |

Keys keep today's encoding for characters Firebase rejects (dot, dollar, hash, brackets), so Outlook message ids and patch file names stay valid. Write path: save() diffs the in-memory state against the last server snapshot and sends one multi-location update containing only the changed fields (new records, changed fields, deleted fields as null). Listen path: child_added, child_changed, child_removed per collection, patched into S in place. Two people editing different records no longer overwrite each other; two people editing the same field still resolve last-writer-wins, at field level instead of blob level.

Deliverables: `tools/migrate.html` (sign in as Leif, copies the blob to crm_legacy, writes the new layout, verifies record and touch counts), `database.rules.json` generated by tools/rules.py (verified allowed emails read and write crm, Leif only on crm-config and crm_legacy), and an exporter that reassembles today's `KinetixCRM Backup.json` shape in key set and content, so sync_diff.py, _outlook_bridge.py, _linkedin_build.py and the Apps Script backup keep working unchanged. Deviation from the brief: dash is split under crm/dash instead of sitting as one 460 KB value under crm/meta, because the daily sweep touches single to-dos.

## 3. Home screen (replaces the Overview tab)

One queue for today, sorted overdue first, then due today, then cadence, promises, stale: due and overdue next actions on any record, letter cadence steps due, open promises (next actions that start with "Promised"), live deals without a next step, revisit dates reached. Each row: name, type chip, the step, due chip, last contact, and the row actions Done, +1w, +1m, Ignore (existing semantics). Beside it the weekly scorecard, Monday to Sunday: letters out vs target 10, replies received, meetings held, names received from partners, live deals without next step. Clicking a scorecard number filters the queue. Dashboard to-dos keep only non-record to-dos (already enforced), Open Items keep the "hide scheduled" default, the former Overview sections (this week, more hints, recent activity, global search) move into the Home page as collapsed blocks or into Ctrl+K.

## 4. Record page

Route `#rec/{id}`, a single scrolling page: header with name, kind, stage or status, star, back link. Sections: details as click-to-edit fields (click a value, edit, blur or Enter saves that one field, Escape cancels), next step and promises (open promises parsed from next-action lines and the action log), letter and cadence, people, shared names, log activity, timeline, files, deal maths (collapsed), danger zone (archive, delete). The modal and saveProfile go away; every call site of openProfile routes to the page.

## 5. Ctrl+K palette

Overlay with one input: type to find any record (same fuzzy search as today's global search), arrow keys and Enter open it, Tab cycles the two inline actions Log call and Set next action which run in the palette without leaving the current view.

## 6. Phone layout

Below 720 px: header collapses to the title plus a menu button holding Sync, Updates, Undo and Sign out; the connection bar collapses to one status line; tabs scroll horizontally; organisation, people, pipeline list and home queue render as stacked cards with field labels, no table wider than the screen; record page sections stack. Desktop unchanged.

## 7. English UI

All chrome in English: pipeline board columns, view buttons, KPI tiles, due chips, cadence step labels, letter status, toasts, prompts, dashboard cadence weekdays, the Open Items note. Record content (notes, next actions, thread drafts, call notes) stays as written.

## Testing

Local harness: a generated copy of index.html with the Firebase, MSAL and Google scripts replaced by an in-memory stub that serves the current `KinetixCRM Backup.json` from the Drive folder (data copied to a gitignored folder, never committed), served by python http.server and driven in the built-in browser. Checks: every tab renders without console errors, migration of the blob produces the layout above, export of the migrated store equals the input backup, a patch file applies with the same made and skipped counts as the old code, record edits produce single-field writes.
